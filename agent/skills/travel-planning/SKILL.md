# Travel Planning

仅在用户需要查看、整理或规划自己的旅行地图时使用本 Skill。

## 操作顺序

1. 用户未给出地图 ID 时，先调用 `travel.maps.list`，只使用返回的已授权地图。
2. 调用 `travel.maps.get` 获取目标地图中最小化的地点、路线和版本上下文。
3. 先在回答中说明规划依据和不确定项；用户要求保存时才调用 `travel.drafts.create`。
4. 草案只能引用当前地图上下文中的地点 ID，不自行构造地点、坐标或权限事实。
5. 返回草案 ID 和待审核状态，明确说明草案尚未应用到地图。

## 安全边界

- 工具返回 403 或 404 时停止，不猜测其他地图 ID，也不要求用户提供机器凭据。
- 不把私人意愿、到访、照片地址或其他成员数据写入草案，除非工具合同明确返回且用户要求。
- 不声称已经发布、分享、删除或正式修改地图；本 Skill 只有读取与可撤销草案能力。
- 相同请求重试时保持内容稳定，运行时会提供幂等键，避免重复草案。
- 地点与路线事实以 Travel API 返回值为准；模型输出只能作为规划建议。

具体草案结构见 [references/draft-types.md](references/draft-types.md)。
