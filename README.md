# Shadow Travel

面向个人旅行规划、途中使用与旅行归档的独立应用。

项目以地图为主要交互入口，把一次旅行中的地点、每日行程、路线、照片、笔记、清单和费用组织在一起。产品从一开始按全球旅行设计，但首个可用版本只聚焦国内旅行；海外能力暂不实现，只在数据模型和地图边界中预留扩展空间。

## 项目边界

- `shadow-travel` 是独立业务应用，拥有自己的前端、后端、数据库与部署流程。
- `shadow-garden` 继续作为个人门户和内容展示站，只提供旅行应用入口，不承载复杂旅行功能。
- 首版不做旅行社区、攻略交易、酒店机票预订或面向公众的商业化服务。
- 用户创建的行程、照片、笔记与费用数据由自己的服务保存；地图平台只承担地图展示、地点检索、地理编码和路线规划等能力。
- 国内使用高德地图，国际使用 Google Maps；业务数据通过统一地图适配层访问两类平台，不直接依赖某一家地图的专有结构。

## 首版目标

1. 创建和管理旅行，记录目的地、日期、同行人及状态。
2. 按天编排行程，支持地点、时间、停留时长、交通方式和备注。
3. 在地图上搜索、收藏和选择地点，展示每日路线与全部旅行足迹。
4. 保存旅行清单、预算和实际费用。
5. 上传照片并编写旅行笔记，旅行结束后形成可回看的归档。
6. 优先适配手机浏览器，并具备 PWA/离线行程的演进空间。

## 初步技术方向

> 以下是下一阶段设计的起点，不是不可变更的最终方案。

- 后端：Python + FastAPI
- 数据库：PostgreSQL
- 前端：独立 SPA/PWA
- 地图：国内使用高德地图，国际使用 Google Maps；首版只接入高德
- 图片：文件存储与数据库元数据分离，优先利用自有 NAS
- 部署：独立服务，计划使用 `travel.cylunex.top`
- 鉴权：首版单用户，预留同行协作所需的用户与权限模型

### 地图策略

- 当前国内版使用高德地图 JS API 与 Web 服务 API。
- 后续国际版使用 Google Maps Platform，并按国家或地区选择地图实现。
- 前后端分别抽象 `MapProvider`、`PlacesProvider` 和 `RoutesProvider`，屏蔽地点搜索、地理编码、路线规划等平台差异。
- 地点表保存平台无关的业务快照，平台地点 ID、坐标系和原始响应作为来源信息单独保存，避免切换地图时迁移全部业务数据。
- 地图 Key、服务端 Key、域名白名单、调用配额和费用告警分别管理，密钥不进入仓库。

高德个人认证开发者可在个人研究、学习和产品测试阶段使用免费月配额；Google Maps Platform 采用按量计费，并为不同 SKU 提供每月免费调用额度。实际发布或商业化前，需要重新核对两家平台当时的许可、覆盖范围和计费规则。

## 全球化预留

国内首版仍按全球化语义设计底层数据：

- 国家或地区使用标准代码，时区使用 IANA 时区标识。
- 金额同时保存币种与数值，不假设所有费用均为人民币。
- 日期时间区分发生地当地时间与统一时间，避免跨时区行程错位。
- 地点明确记录坐标系和地图来源，不把某个平台的地点 ID 当作唯一标识。
- 文本、地址和单位为多语言及本地化展示预留字段或转换边界。

## 预期领域模型

- `trips`：旅行主档
- `trip_days`：旅行日程
- `places`：用户选中的地点快照
- `place_provider_refs`：高德或 Google Maps 等平台的地点标识与来源信息
- `itinerary_items`：按天编排的行程项
- `routes`：交通方式与路线结果
- `checklists`：行前和途中清单
- `expenses`：预算及实际费用
- `notes`：旅行笔记
- `media`：照片与附件元数据
- `companions`：同行人及未来协作关系
