# Shadow Travel

一个以地图为中心、支持个人记录和同行协作的主题地点收藏工具。

Shadow Travel 用来创建和维护“北京公园年票”“贵阳美食之旅”这样的主题地图。用户可以在地图上收藏地点、分类和筛选点位、记录想去与到访状态、上传照片，并与少量同行人共同维护内容。路线规划是可选能力，不是产品主线。

## 产品定位

- 地图是主要入口，列表是补充视图。
- 一张主题地图可以只有一名成员，也可以邀请同行人协作，不区分独立的“个人版”和“多人版”。
- 现实地点、地图内的共享内容、成员在该地图中的计划意愿，以及个人的到访历史分开保存。
- 到访、照片和个人体验跟随现实地点跨地图复用；“这张地图里想不想去”仍属于具体主题地图。
- LLM 和 Agent 是可选增强层，负责理解、整理和生成草案；地图事实、权限判断和最终写入仍由确定性服务完成。
- 不建设论坛、关注、评论流、攻略交易或公开社区。
- 首版面向国内使用并实现高德地图；架构预留 Google Maps 国际 Provider，但不在首版开放。

## 核心概念

### 全局地图

聚合当前用户有权访问的所有主题地图和点位。用户可以按主题地图、分类、标签、城市、成员和到访状态筛选。全局地图只是一种聚合视图，不复制点位数据。

### 地点库

地点库保存用户和同行人使用过的现实地点。一个地点可以被多张主题地图引用，到访历史、个人照片和体验记录不因地图不同而重复创建。

### 主题地图

围绕一个主题组织地点，例如：

- 北京公园年票 2026
- 贵阳美食之旅
- 去过的博物馆
- 周末露营地点

每张地图包含名称、简介、成员、默认地图视野、点位、分类和可选路线。地图可以设置统计周期和进度规则，也可以只复制共享点位生成下一年度或另一个版本。

### 地点与地图点位

点位信息分为三层：

- 地点事实：地点名称、坐标、地址、地图来源等现实位置快照。
- 地图内容：分类、标签、公共备注、外部参考链接、自定义属性和在当前主题地图中的显示方式。
- 成员计划：某名成员在当前地图中想去、计划去或不考虑。

到访记录、评分、个人备注和照片属于成员与现实地点，可以跨主题地图复用。记录归对应成员所有：从主题地图创建时默认对该地图成员可见，从全局地点库创建时默认仅自己可见，不会因为同一地点出现在其他地图中而自动扩大权限。是否去过不只保存为布尔值，而是由一条或多条到访记录推导得出。

### 展示模式

主题地图可以切换到展示模式，只展示共享点位和介绍；切换到成员视图后，再叠加个人或同行人的计划、到访记录和照片。后续可通过只读链接分享指定的地图视野和筛选结果。

## 首版范围

### 核心能力

1. 登录并创建、编辑、归档主题地图。
2. 邀请少量同行人成为地图协作者。
3. 通过高德地点搜索、点击地图、粘贴地点链接或手动填写来添加点位。
4. 为点位设置分类、标签、公共备注和少量自定义属性。
5. 每名成员记录在具体地图中的想去、计划去和不考虑，并查看同行共识。
6. 针对现实地点记录可跨地图复用的多次到访、个人备注、评分和照片。
7. 在地图与列表之间切换，并按地图、分类、标签、属性、成员意愿和到访状态筛选。
8. 在全局地图中查看当前用户有权访问的全部点位和个人地点历史。
9. 为地图配置统计周期和进度规则，区分历史到访与本期完成。
10. 批量导入、导出、选择和编辑点位，保证数据可迁移。
11. 复制一张地图的共享内容，用于下一年度或另一个版本。
12. 选择并排序若干点位，展示大致路线；每个地点和下一站均可尝试跳转高德地图。
13. 使用展示模式查看地图，并为后续只读分享预留权限边界。
14. 使用自然语言查询已有地图、提取文本中的地点、建议标签和属性，并生成可审核的批量修改或路线草案。
15. 为外部 Agent 预留受权限控制的工具接口，首版只开放读取和创建草案，不允许绕过应用直接修改数据库。

### 暂不实现

- 费用、预算和多人分摊
- 航班、火车、酒店等专用行程模型
- 按小时编排的详细日程
- 应用内导航和导航级路线
- 论坛、关注、点赞、公开信息流
- 酒店机票预订或攻略交易
- 完整离线模式
- 国际地图和多地图平台切换
- GPS 自动轨迹和后台附近提醒
- 脱离用户数据和地图平台校验的泛化 AI 地点推荐

通用备注和标签可以承载少量交通、住宿等临时信息，暂不为它们开发专门界面。

## 首批使用场景

### 北京公园年票

- 批量导入年票包含的公园。
- 按行政区、类型和标签查看点位。
- 设置年票有效期，只统计有效期内的完成情况，同时保留历史到访。
- 每名成员分别记录自己的到访情况并查看同行进度。
- 为每次游览添加日期、备注和照片。
- 下一年度可以复制共享点位，再调整新增或移除的公园。
- 不依赖路线规划。

### 贵阳美食之旅

- 收藏小吃店、餐厅、夜市等地点。
- 记录分类、推荐菜、人均价格等属性和公共备注。
- 每名成员记录自己的意愿，并筛选“大家都想去”等共识结果。
- 从已有点位中选择若干站点，排序并展示大致路线。
- 上传就餐照片和到访记录。

## 技术方案

- 后端：Python 3.12、FastAPI、SQLAlchemy 与 Alembic
- 数据库：PostgreSQL；SQLite 仅用于本地快速开发和单元测试
- 前端：React、TypeScript、Vite，移动端优先并兼容 PWA 与 ShadowApp WebView
- 地图：领域级 `MapProvider`；国内 AMap，国际阶段 Google Maps
- 图片：Shadow Media 控制面；业务数据库只保存 `media_id`
- 浏览器认证：原生 OIDC Authorization Code + PKCE 与服务端会话
- 机器认证：Agent、后台同步和定时任务使用独立 Bearer，不读取浏览器 Cookie
- 智能能力：Shadow Platform 进程内 LLM SDK + 受控 Agent 工具层
- 规范入口：主站子路径 `/travel/`，本地可在根路径运行

地图相关代码通过适配边界访问地点搜索、地理编码和路线服务。业务数据保存平台无关的地点快照，同时记录地图来源、平台地点 ID、坐标系和必要的原始来源信息，避免将核心模型绑定到高德。

地图 Key、服务端 Key、域名白名单、调用配额和费用告警分别管理，密钥不进入仓库。正式发布前需要重新核对地图平台当时的许可和计费规则。

## LLM 与 Agent 方向

智能能力优先解决已有数据的使用效率，不取代手动地图功能。没有配置模型、模型调用失败或额度耗尽时，地图、筛选、导入、路线和协作仍然完整可用。

首批智能场景：

- 用自然语言筛选已有地点，例如“找出我和小李都想去、在南明区、适合夜宵的店”。
- 从用户粘贴的文字或清单中提取地点候选，再通过高德搜索匹配并让用户确认；外部链接先作为来源保存，服务端网页抓取后置。
- 根据地图已有分类、标签和自定义字段生成结构化填写建议。
- 从已验证点位和成员意愿中生成路线草案，再使用地图路线服务计算距离和耗时。
- 汇总某张地图的到访、照片和成员进度，生成可编辑的回顾草稿。

模型不得凭记忆生成坐标、平台地点 ID、营业状态和路线结果。涉及新增、批量修改、路线保存、分享范围或删除的操作必须先生成结构化变更集，由后端重新校验权限和字段，再向用户展示差异并等待确认。

应用内部通过稳定的 Agent Tool API 暴露最小能力；后续可以在其上提供远程 MCP 接口，让用户授权的外部 Agent 查询地图和创建草案。外部接口按用户身份和地图成员关系鉴权，使用细粒度作用域、限流、审计和可撤销授权，默认不返回照片原文件与私人到访内容。

## 预期领域模型

- `users`：用户
- `maps`：主题地图
- `map_members`：地图成员与角色
- `places`：平台无关的地点快照
- `place_provider_refs`：高德等平台的地点来源信息
- `map_points`：地点在某张主题地图中的共享内容
- `map_point_references`：攻略、社交内容等外部参考链接
- `point_categories`、`tags`：分类和标签
- `map_field_definitions`、`map_point_field_values`：地图自定义属性
- `member_point_preferences`：成员在具体地图中的想去、计划等意愿
- `visits`：成员对现实地点的到访记录，可选保存来源地图上下文
- `visit_map_shares`：到访记录对主题地图的可见范围
- `media`：照片及附件元数据
- `routes`、`route_stops`：可选路线及有序站点
- `share_links`：后续只读分享链接
- `audit_events`：共享内容的重要变更记录
- `agent_sessions`、`agent_runs`：助手会话与执行状态
- `agent_tool_calls`：工具调用、权限判定和结果摘要
- `agent_change_sets`、`agent_approvals`：待审核变更集与用户决策
- `llm_usage_events`：模型、延迟、令牌与费用统计

详细需求与规则见 [首版产品需求](docs/product-requirements.md)。

## 本地启动

Windows 命令统一在 Git Bash 中执行：

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install -e ../shadow-platform -e '.[dev]'
cp .env.example .env
set -a && source .env && set +a
.venv/Scripts/python.exe -m alembic upgrade head
.venv/Scripts/python.exe -m uvicorn shadow_travel.main:app --reload
```

前端：

```bash
cd web
npm install
npm run dev
```

完整说明见 [本地开发](docs/development.md)。示例配置不会提供可用的身份、地图、媒体或模型凭据。

## 开发阶段

1. 工程与安全底座：配置、迁移、OIDC/会话、机器 Bearer、平台适配和 prefix-safe 前端。
2. 地图核心：主题地图、成员、地点、点位、筛选和北京公园年票。
3. 记录与媒体：到访、备注、Shadow Media 上传与照片权限。
4. 粗略路线：贵阳美食地图、站点排序、高德路线和外部跳转。
5. 智能增强：自然语言查询、地点提取、路线草案和审核变更集。
6. Agent/MCP：最小权限的读取与草案工具、委托授权、幂等和审计。

## 当前状态

后端已按最终产品设计完成领域基线：Place 与 MapPoint 分离，Provider 地点标识按所有者隔离，Preference 带主题作用域，Visit、VisitMapShare、VisitRecord 与 Photo 分层保存；主题支持周期进度、成员协作、点位筛选和批量编辑、逐行容错且有容量边界的 CSV/GeoJSON 导入导出、自定义字段、地图复制、路线、游标分页的共享记录时间线、可撤销只读分享、共享内容审计，以及受控 LLM/Agent 路线草案。照片默认私密，只有本人或被主动共享到目标主题的记录成员可以读取元数据和短时地址；时间线照片数使用聚合查询，公开链接访问时间采用写入节流。

Web 仍是用于验证交互方向的前端原型，尚未接通全部后端管理能力。ShadowApp 壳接入按当前安排后置，Web 已保留子路径、文件选择、顶层登录跳转和后台同步边界，具体缺口见接入状态文档。
