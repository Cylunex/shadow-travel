# 旅行闭环实现与验收（2026-09）

本轮复用原 React / Router / TravelContext / MapSurface / 高德及 FastAPI / SQLAlchemy 架构。
这是研究方案在本仓库内的第一轮实现，不把外部平台、原生定位和离线地图许可包装为已完成。

## 已实现的纵向流程

| 范围 | 实现 | 限制与真实边界 |
| --- | --- | --- |
| S0 可靠性 | IndexedDB 按实例/账号隔离；逐项确认 Outbox；跨标签 Web Locks；写入 owner 校验；401/409 停止或保留冲突；旧队列导出 | 本机数据未加密，逻辑隔离不抵御同源 XSS；无主旧数据不自动认领 |
| S0 上下文 | 显式主题详情路由、mapPoints selector、备注版本、独立意愿；本地/旅程时区日期；WGS84 转高德；未知路线不显示 0 | 地点资料仍需来源核验；不把直线当导航结果 |
| S1 地点捕获 | 文本/链接/按行清单收集；高德候选/选点/手工坐标/已有收藏确认；来源与原因；独立收藏和归入主题 | 不自动抓取网页、不让模型创造 POI；相同所有者的 provider ID 去重，不做模糊自动合并 |
| S2 规划 | Trip 创建、日期/时区、候选池、日程编辑、拖动/按钮排序、锚点、预约摘要、任务/责任人、预算、成员权限 | 预约是共享摘要而非 OTA 预订；不填证件号和确认码；资料 URI 不授予访问权限 |
| S2 版本 | 保存草稿 + 显式确认；base_revision CAS；确认快照；历史版本恢复为新草稿；日期/重叠检查 | 交通时长可手工估计且标明；营业/天气/无障碍未核验不会伪称可行 |
| S3 旅途 | 确认计划中的日期/下一站/地址/外部导航/到访；移动三态面板；已确认 Pack；存储管理；ICS/打印 | Pack 仅含计划、地点和本人到访，7 天过期，不含底图、路线几何、照片及票据原件 |
| S3 离线 | 构建清单预缓存；只管理自身静态缓存；本地副本冷启动；显式本地读取，不冒充在线认证；断网到访队列 | 首次使用需要在线；未下载旅程不能离线打开；撤销权限无法远程立即抹掉离线副本 |
| S4 记忆 | 私密 Memory / Journey，引用原 Visit/片段/已有 Travel 照片；记录编辑与导出 | 不复制照片；跨应用全局资产浏览仍需独立授权接入；公开 Journey 投影后置 |
| S4 路径 | 有界 GPX 解析、分段/时间/可空海拔、几何预览、距离、保存和导出 | 仅参考路径，不等于 TrackSession、DetectedStay 或真实到访；不是户外导航 |
| S5 可解释建议 | 有界就近排序，锚点和日期不变；差异/假设/有效期/冲突展示；用户采用到草稿再确认 | 确定性启发式，非最优保证、非道路交通矩阵；现有主题 AI 路线能力保留 |

## 数据与权限

- 新增前向迁移 `20260904_0006`：Capture、TripMember、Plan、PlanVersion、Experience；不重命名旧表。
- Plan 的主题来源不继承主题所有者权限。Trip 同行仅获得本次候选地点事实与规划内容；不能修改他人的 Visit Record。
- Memory / Journey / Trail 始终私密。删除回忆不删除 Visit 或资产。
- 服务端每次检查成员权限；前端请求的 `X-Travel-Owner` 进一步阻止换号过程中的串写。
- 离线 Pack 与既有带校验的 Bundle 分开。Bundle 仍是隔离验证，不宣传完整资产恢复。
- 有编辑冲突时不静默覆盖；保留当前草稿，允许导出，再显式加载服务器版本。
- 高德外跳遵循 [单点标注坐标参数](https://lbs.amap.com/api/uri-api/guide/mobile-web/point) 与
  [路径规划 URI 限制](https://lbs.amap.com/api/uri-api/guide/travel/route)：不静默忽略多站路线的中间地点，无法携带整条路线时明确提示首段导航。

## 开发验收

```bash
npm --prefix web run typecheck
npm --prefix web run build
npm --prefix web test
npm --prefix web run test:e2e
.venv/bin/python -m pytest -q
.venv/bin/python -m ruff check server/src/shadow_travel
```

前端单测使用 fake-indexeddb；浏览器测试使用本机 Chrome 与明确标注的 API 测试夹具，
覆盖 390、430、768、1280、1440 px，以及真正的 Service Worker 冷启动。
后端测试使用临时 SQLite + TestClient，验证真实路由/模型/会话/权限，并非页面模拟结果。
生产 PostgreSQL 的锁竞争、真实高德网络、移动真机续航与原生权限尚需部署前环境验收。

本轮结果：60 项后端测试、10 项前端单测、8 项浏览器测试通过；类型检查、生产构建、Ruff 与 Git 空白检查通过。
浏览器覆盖缓存 `Vary: Origin` 差异、断网时 `navigator.onLine` 仍为 true 的冷启动，以及恢复在线后仅重放一次。

迁移在独立临时数据库执行到 head，并通过 `alembic check` 验证模型与迁移一致；
未修改用户日常开发数据库、未连接生产数据库、未部署。
