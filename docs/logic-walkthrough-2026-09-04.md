# 全流程逻辑走查与修复

本轮基于既有实现做三轮走查：正常业务链路、数据归属与版本边界、失败/断网/重试及页面切换。没有重写后端、迁移生产数据或部署。

## 覆盖范围

| 链路 | 走查重点 |
| --- | --- |
| 收集 → 地点 → 主题 | 批量部分失败、重复确认、来源引用、意愿与到访分离、共享属性权限 |
| 主题地图 → 路线 | 空列表、服务不可用、出行方式与排序保存失败、坐标与地图 Provider 边界 |
| 旅程 → 草稿 → 确认 | 稳定站次 ID、旧确认版、跨时区顺序、DST、路段端点、交通方式 |
| 确认 → 旅途中 | 执行版本不自动换版、成员独立状态、同地多站、到访复用、页面切换中断网 |
| 到访 → 照片 → 回忆 | 上传不能创造到访、个人记录编辑、退出同行后的个人数据、撤权后的分享限制 |
| 离线 → 重放 | 原账号归属、写入中切换账号、过期副本、旧 Run 版本、丢响应重试、冲突保留 |
| 既有服务边界 | 全量后端测试复核导入导出、分享链接、字段、分页、GPX、OIDC、机器凭据与同源保护 |

## 已修复的问题

1. 新确认计划移除候选后，旧 Run 的地点从成员工作区和计划目录消失。目录现在包含草稿、当前确认版与实际执行版需要的地点，不修改旧版本。
2. 退出主题/旅程后，自己的到访被地点访问过滤一起隐藏。个人到访及事实仍可读、个人记录可改；原主题共享内容、旅程计划及离线包权限不保留。
3. 私人回忆保留已撤权旅程来源时无法编辑。允许保留原引用，不允许新挂接已无权限的旅程。
4. 执行命令响应只含自己，导致已主动共享的同行状态暂时消失。响应使用与 GET 相同的授权投影；持久幂等回执仍只存自己的状态。
5. 前端按当地钟表排序，和后端实际时间顺序不一致。站次展示、路段编辑/清理、v1 升级统一按时区与 DST 消歧后的时间；无效时间不猜偏移、不提前丢弃估计。
6. 非相邻路段的估计可能被静默忽略。后端确认检查明确报错；Plan v2 交通核验读取 Segment 的方式，不再误用旧 Stop.mode。
7. 路线不足两站可能残留旧几何/统计；保存方式或排序失败却先改变 UI。清空无效结果，保存确认后才更新本地路线状态。
8. 编辑旧站次可更换地点，但后端稳定身份校验必然拒绝。禁用该选择并说明应新建站次；回忆编辑同样不能改类型。
9. 批量收集部分失败、新建旅程丢响应后重试生成新的 ID。现在保留重试身份，收集 API 使用既有幂等回执表，不新增表。
10. 下载旅行副本/创建本地队列期间切换账号，可能在异步完成时写入新账号范围。捕获原作用域、写前复核并显式写入原作用域；旧格式副本也复核。
11. 离线执行仅核对 Run ID，未核对绑定版本/站次；非法到期日期也可能被当作有效。补齐检查。
12. 下载完成后准备清单不刷新；返回旅途中时断网可能丢失内存 Run。下载事件刷新清单，切换页签保留原执行状态。
13. 地点详情照片 effect 依赖每次重建的地点对象，引起重复请求和旧结果覆盖。改为稳定上下文依赖、请求序列检查，并隔离不同地点/主题的照片展示。
14. 旧照片上传会自动创造“今天到访”并共享完成。上传现在必须明确选择本人已有到访；过期旧上传意图没有 Visit 时拒绝完成，不创建伪事实。
15. “补照片和记录”只提供浏览，没有修改原记录的入口。新增按到访编辑文字、评分的小对话框，携带 expected_version，不改变原共享范围；服务器锁定到访行后检查版本。
16. 撤权成员可再次把个人记录设为原主题共享。重新共享要求仍有主题访问权；改回私密/编辑私人文字不受影响。
17. 海外搜索执行中还可切换国家、城市，造成响应和当前表单错配。执行期间锁定上下文；城市长度与后端一致。
18. 到访总数标为“今年到访”。更正为全部到访，并明确包含待同步记录；待同步记录不提前推导为已到访状态。
19. 新照片继承已共享 Visit Record 的可见性，却宣称默认私密。共享记录必须由用户主动改回私密后才允许追加照片；上传创建和完成均检查，已有照片的显式共享能力不变。

## 验证与边界

- Python 全量测试 75 项通过；前端单测 14 项通过。
- Chrome 回归 21 项通过，覆盖 390、430、768、1280、1440 px，增加重试、字段身份、清单刷新、路段方式、失败保存、照片所属到访和请求次数检查。
- TypeScript typecheck、生产 build、源码/测试 Ruff、git diff --check。
- 测试使用临时数据库与可控 Provider/媒体夹具；不等同于 Google、高德、媒体存储真实账户与网络环境的端到端验收。
- 本轮没有调用生产地图计费接口，没有修改生产库，没有推送或部署。

兼容注意：照片上传创建接口现在要求 `visit_id`；前后端应一起发布。未完成的旧无 Visit 上传意图需重新选择到访后上传。独立地点尚无主题时，照片上传入口明确不可用，已有到访和文字记录仍可用。旧日期/时区存在冲突的计划需人工核对，不能靠猜坐标或时间自动修正。
